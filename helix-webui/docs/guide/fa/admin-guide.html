۱. معرفی Helix

Helix یک سامانهٔ تحلیل هوشمند روی انبار داده است. کاربر با زبان طبیعی سؤال می‌پرسد؛ خط لولهٔ چندعاملی (LLM pipeline) فقط پرس‌وجوی SELECT تولید و اجرا می‌کند و خروجی ساخت‌یافته برمی‌گرداند: گزارش متنی، جدول داده و/یا نمودار ECharts.

محصول از دو بخش تشکیل شده است:

  • helix-api — بک‌اند Django با REST و SSE؛ اجرای خط لوله، اتصال به انبار، ذخیرهٔ تنظیمات در helix.config.yaml
  • helix-webui — رابط React برای مدیر و تحلیل‌گر؛ تنظیمات، عامل‌ها، نتایج و خروجی PDF
نکته
Helix یک اپ CRUD کسب‌وکار نیست؛ روی خواندن انبار (SELECT-only) و تحلیل متمرکز است. نوشتن، DDL و EXEC پشتیبانی نمی‌شود.

خط لولهٔ پیش‌فرض

guardian → data-gatherer → validator → result-builder → validator → publisher
عامل نقش
نگهبان (guardian) بررسی امنیت درخواست و مجوز دسترسی کاربر
جمع‌آور داده (data-gatherer) نوشتن و اجرای SELECT؛ دریافت ردیف‌ها (سقف ۵۰۰)
اعتبارسنج (validator) آیا داده با سؤال کاربر هم‌خوان است؟ (دو بار اجرا)
سازندهٔ نتیجه (result-builder) گزارش تحلیلی از ردیف‌های واقعی
ناشر (publisher) بسته‌بندی خروجی UI (گزارش / جدول / نمودار)

۲. راه‌اندازی اولیه

اجرای محلی

  1. ابتدا API را راه بیندازید (Python 3.12، پورت ۸۰۰۰). جزئیات در README پروژهٔ helix-api.
  2. سپس Web UI: 
    npm install
npm run dev
    آدرس پیش‌فرض: http://127.0.0.1:5173 — در توسعه، /api به Django پروکسی می‌شود.
  3. در صفحهٔ /settings کلید API مدل زبانی را وارد کنید.

Docker

هر دو پروژه Dockerfile و docker-compose دارند. API روی پورت ۸۰۰۰ و Web UI پشت nginx سرو می‌شود. فایل helix.config.yaml باید قبل از اجرا وجود داشته باشد.

نشانگرهای سلامت

در نوار کناری سه وضعیت نمایش داده می‌شود: مدل زبانی، موتور و پایگاه داده. روی آن‌ها کلیک کنید تا به زبانهٔ گزارش وضعیت در تنظیمات بروید.

هشدار
اگر «دسترسی به API ممکن نیست» می‌بینید، سرور helix-api در حال اجرا نیست یا پروکسی/نشانی پایه اشتباه است.

۳. تنظیمات عمومی

مسیر: /settings → زبانهٔ عمومی

نام و نشان شرکتی که از Helix استفاده می‌کند را اینجا تنظیم کنید. این اطلاعات در سربرگ برنامه و خروجی PDF نتایج تحلیل دیده می‌شوند.

  • نام شرکت — متن نمایشی در هدر
  • نشان شرکت — PNG یا JPEG، حداکثر ۲۵۰ کیلوبایت

پس از تغییر، دکمهٔ ذخیره را بزنید. تنظیمات در API ذخیره می‌شود.

۴. مدل زبانی

مسیر: /settings → زبانهٔ مدل زبانی

اجراهای تحلیل یک API گفت‌وگوی سازگار با OpenAI را صدا می‌زنند. سه ارائه‌دهنده پشتیبانی می‌شود:

ارائه‌دهنده کاربرد
OpenRouter پیش‌فرض رایج؛ مدل‌های متنوع از یک کلید
سازگار با OpenAI میزبان دلخواه با نشانی پایهٔ سفارشی
Cursor کلید Cloud Cursor + آداپتر محلی روی میزبان API

فیلدهای مهم

  • نشانی پایه — مثلاً OpenRouter یا OpenAI
  • کلید API — روی میزبان API ذخیره می‌شود، نه در مرورگر
  • مدل پیش‌فرض — برای عامل‌های بدون مدل اختصاصی
  • مدل هر عامل — override برای guardian، data-gatherer و غیره
نکته
برای Cursor، برنامه باید روی ماشین API نصب باشد و آداپتر محلی (پورت ۸۱۳۰) در دسترس باشد.

تنظیمات در helix.config.yaml ذخیره می‌شود.

۵. پایگاه داده

مسیر: /settings → زبانهٔ پایگاه داده

نمونهٔ SQLite (AdventureWorks)

به‌طور پیش‌فرض، API از پایگاه نمونه AdventureWorks LT استفاده می‌کند. سه سطح (کوچک / متوسط / بزرگ) قابل دانلود و فعال‌سازی است — برای آزمایش بدون اتصال به انبار واقعی.

انبار واقعی

موتورهای پشتیبانی‌شده:

  • PostgreSQL — میزبان، درگاه، SSL
  • SQL Server — ODBC Driver 18، رمزنگاری، اعتماد به گواهی
ODBC و SQL Server
از Python 3.12 استفاده کنید (pyodbc روی 3.15 بدون wheel سخت است). خطای 08S01 یعنی قطع ارتباط TDS — اتصال شبکه، فایروال و پایداری سرور SQL را بررسی کنید.

رشتهٔ اتصال را ویرایش و ذخیره کنید تا فیلدهای میزبان، کاربر و گذرواژه به‌روز شوند.

۶. مدیریت کاربران

مسیر: /admin

کاربران Helix «هویت شرکت» با سیاست دسترسی به داده هستند — نه ورود با رمز عبور کلاسیک. هر کاربر فیلدهای زیر را دارد:

  • نام کاربری و نام نمایشی
  • مدیر — دسترسی کامل SELECT
  • دسترسی به داده — توضیح زبان ساده (مثلاً «فقط جداول فروش»)

هنگام ایجاد/ویرایش کاربر غیرمدیر، عامل نگهبان سیاست دسترسی را بررسی و به جداول مجاز نگاشت می‌کند.

مدیر پیش‌فرض
کاربر armin همیشه seed می‌شود و قابل حذف یا تنزل نیست.

اگر Web UI نام کاربر را در درخواست اجرا ارسال نکند، اجرا به‌عنوان مهمان (guest) ثبت می‌شود.

۷. قوانین و مهارت‌ها

مسیرها: /rules و /skills

مفهوم کاربرد
قوانین (Rules) سیاست‌ها و محدودیت‌های ثابت (مثلاً قرارداد خروجی، امنیت SQL)
مهارت‌ها (Skills) دستورالعمل‌های عملیاتی و playbook برای وظایف خاص

عملیات

  • ایجاد، ویرایش، حذف — محتوا به‌صورت Markdown
  • فعال / غیرفعال کردن
  • تخصیص به عامل‌ها از صفحهٔ تخصیص هر عامل
نکته
عامل‌ها فقط از قوانین و مهارت‌های تخصیص‌یافته استفاده می‌کنند — فایل instruction جداگانه ندارند.

۸. عامل‌ها و خط لوله

مسیر: /agents

سه نما

  • فهرست — لیست عامل‌ها با قوانین/مهارت‌ها
  • چینش (Arrange) — مرحله‌به‌مرحله IF/ELSE/برو به؛ هر مرحله یک «اگر»
  • گراف (Graph) — نمای بصری همان جریان چینش

شرط‌های رایج

  • موفق / ناموفق / تلاش دوباره
  • نتیجه برابر است (مثلاً done)
  • آنگاه: برو به عامل بعدی یا توقف

می‌توانید عامل سفارشی بسازید (شناسه، نقش، توضیح) و قوانین/مهارت‌ها را از /agents/:id/assignments تخصیص دهید.

هشدار
خط لولهٔ پیچیده بدون IF منظم در چینش، در نمای گراف به‌درستی نمایش داده نمی‌شود. از «بازنشانی پیش‌فرض» برای بازگشت به جریان خطی استفاده کنید.

۹. مستندات جداول

مسیر: /docs

ویرایشگر مستندات انبار: برای هر جدول «نمای کلی» و برای هر ستون «توضیح» و «توضیح SQL» قابل ویرایش است.

این توضیحات به کاتالوگ زندهٔ API می‌پیوندد و به عامل data-gatherer کمک می‌کند SELECT دقیق‌تری بنویسد — به‌ویژه برای جداول با نام‌های فارسی/اختصاصی.

توصیه
برای ستون‌های مبهم، توضیح SQL (معنی فنی برای مدل) را پر کنید؛ کیفیت تحلیل به‌طور محسوس بهتر می‌شود.

۱۰. کاوشگر پایگاه داده

مسیر: /db-explorer

ابزار تشخیصی مدیر: انتخاب جدول، WHERE، ORDER BY، محدودیت تعداد ردیف و اجرای پیش‌نمایش فقط SELECT.

برای بررسی اینکه آیا داده در انبار وجود دارد، قبل از اجرای تحلیل LLM مفید است.

۱۱. کانواس PDF

مسیر: /canvas

طراحی چیدمان خروجی PDF نتایج تحلیل. تنظیمات در localStorage مرورگر ذخیره می‌شود (هر دستگاه جدا).

گزینه‌های چیدمان

  • نوار سربرگ، لوگوی Helix، لوگوی شرکت
  • عنوان (پرسش)، نمودارها، گزارش متنی، جدول داده
  • پاورقی صفحه
  • جهت افقی / عمودی
  • ضخامت و گردی حاشیه، قلم (پیش‌فرض: وزیرمتن)

از صفحهٔ جزئیات نتیجه (/results/:id) دکمهٔ «خروجی PDF» فایل را با همین چیدمان تولید می‌کند.

۱۲. گزارش‌ها و عیب‌یابی

مسیر: /logs

انواع گزارش

نوع معنی
pipeline شکست در خط لولهٔ عامل‌ها
llm خطای مدل زبانی یا API
sql خطای پرس‌وجوی SQL
database اتصال یا موتور پایگاه داده
api خطای سطح API

مشکلات رایج

  • دسترسی به API ممکن نیست — API خاموش یا پروکسی اشتباه
  • کلید API تنظیم نشده — زبانهٔ مدل زبانی در تنظیمات
  • pyodbc / 08S01 — Python 3.12، پایداری شبکه SQL Server
  • API نادرست پیکربندی شده — HTML به‌جای JSON؛ نشانی پایه را بررسی کنید

زبانهٔ گزارش وضعیت در تنظیمات رویدادهای لحظه‌ای اتصال را نشان می‌دهد؛ گزارش‌های ذخیره‌شده در صفحهٔ گزارش‌ها می‌مانند.

۱۳. محدودیت‌ها و امنیت

  • فقط SELECT — INSERT، UPDATE، DELETE، DDL و EXEC ممنوع
  • بدون دادهٔ ساختگی — خروجی باید از ردیف‌های واقعی انبار باشد
  • سقف ردیف — خط لوله حداکثر ۵۰۰ ردیف در هر fetch (قابل تنظیم در config)
  • کاتالوگ — عامل‌ها نباید جدول/ستونی خارج از allowlist اختراع کنند
  • نگهبان — درخواست‌های jailbreak، credential fishing و دسترسی غیرمجاز را رد می‌کند
  • مهمان — بدون username در درخواست، actor مهمان است
